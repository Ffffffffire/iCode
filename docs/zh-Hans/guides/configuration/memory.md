# 配置记忆

使用 `/memory` 管理个人经历和决策；使用 `/agents memory` 配置随智能体加载的参考文件。

第一次试用可跟随[个人记忆演示](memory-demo.md)，依次体验保存、跨会话使用、更正和停止使用。

## 个人记忆

个人记忆保存你希望延续到以后任务的选择依据、偏好、经验和未完成意图。值得记住的内容，要么能在某类情境中帮助判断和行动，要么是你明确希望保留、以后找回的事情。一次失败不能自动变成“你不适合做什么”的长期判断。

| 内容 | 放在哪里 |
| --- | --- |
| 跨任务的个人偏好、选择理由、长期意图 | 个人范围，例如“对客户介绍方案时，先讲价值和落地，技术细节留到问答” |
| 某个仓库的约束、项目决策和排查经验 | 仅当前项目，例如“这个项目报告旧版本未失效，查缓存前先核对产物版本” |
| 当前进度、一次性的要求、很快变化的运行状态 | 当前对话、任务摘要或待办；不要默认转成长久规则 |
| 整篇资料、团队规范、工具说明 | 参考文件或项目文档；加载过不等于它描述了你的个人偏好 |

个人记忆库中的项目条目仍由你管理，不会自动发布为团队共识。共享知识需要单独核对适用对象、证据和维护责任。任务压缩摘要可以帮助找回待续事项，但重复摘要不能增加一条长期记忆的可信度。

### 记一条就够用

点击会话底部的 **记忆**，或输入 `/memory`。有建议时，入口显示 **待确认** 并直接打开候选；有召回时，入口显示 **参考** 并打开 **本轮参考**。日常对话不会因为这些提示被打断。

点击 **+ 记一条**（`Ctrl+N`），写下要记住的内容，按 `Ctrl+Enter` 保存。标题默认取内容的第一行；需要分类、标题、适用情境或重新考虑的条件时，展开 **更多选项**。默认勾选 **仅当前项目**，取消后可跨项目使用。保存前不需要填写一套表格。

也可以在聊天中明确说“请记住……”“请帮我记住……”或“更新这条记忆……”。主智能体核对本轮用户原话后直接保存，不再生成一条需要重复确认的建议。代码块、引用中的“记住”以及被否定的指令不能单独授权保存。明确说“不要记住”的内容也不能作为候选建议保存，即使已开启提炼建议。指令含混或未被识别时，可以直接在 `/memory` 记一条。

可以先表达偏好，随后说“润色后帮我记住这条偏好”或“帮我整理并记住”。本轮的明确请求负责授权保存，记忆来源可以引用前文真实的用户原话，不必在同一句话里重复全部内容。工具返回等中间步骤不会占用近期原话的数量限额。润色应保留原来的适用范围，不应添加未经确认的效果、例外或结论。

聊天提炼每条最多 600 字符，保留一个简短结论及适用情境；有必要时再加理由和重新考虑的条件。超过长度会要求重新提炼，不会截掉后半段。比如“做任何设计都不能增加字段”过于绝对；“扩展轨迹 IR 前先确认消费方；已有消费方能证明新增字段改变了产出时再扩展”更容易执行，也允许经验随证据改变。手动编辑仍可保留较长内容，最多 2,400 字符。

在记忆库底部选择保存方式，默认是 **明确要求才保存**：

- **明确要求才保存**：日常对话不自动提取。说“帮我记住”或“把这个偏好留着，下次也这样”时，会结合上下文理解、润色并保存。
- **自动记住明确偏好**：每个新回合检查当前表达；直接说出的稳定偏好自动保存并生效，推断的经验、决定和意图先进入待确认。原来已开启“提炼建议”的设置会采用此方式。
- **全部先确认**：自动提炼，但新记忆先进入待确认；你明确要求直接保存时仍直接保存。

开启自动提炼后，使用当前对话的模型，每个新回合最多增加一次自动提取请求，因此开始回答前会多一些等待。底部显示 **记忆 · 提炼中**；真正保存后提示 **已记住：标题**，候选提示 **待确认记忆：标题**。没有值得记的新内容时不新增条目。提取失败会提示，不会宣称已经保存，也不阻止继续对话。

润色保留原意，通常整理成一两句可以独立理解的表达；不把口语扩写成规范长文，不添加你没说过的例外或“已验证”的效果。偏好、决定和意图必须引用用户原话；助手原话只能支持待审的经验。候选直接显示来源，检查后点 **记住**，不需要的点 **忽略**。待审修订在确认前不覆盖已接受的记忆。

### 重复、更新与纠偏

- **意思和条件没变**：内容、适用情境、重新考虑条件、类型和范围相同，仅换标题或首尾空白，不新增一条，也不把重复保存当作新证据。
- **原来的结论错了**：说“更新这条记忆：……”。智能体需要先找到原条目和版本；找不到或不明确时，应定位或询问，不能把更新当成新增。更新保留原来的个人／项目范围，范围调整可在编辑器完成。
- **只是这一次例外**：直接说明“这次……”。当前要求优先，不应据此改写长期偏好。不同适用条件可以各自保留。
- **不确定哪里错了，但暂时不能再用**：打开 `/memory` 对该条目点 **停用**；核对后再编辑或恢复。明确不需要保留时点 **忘记** 并确认删除。

提炼时会对照一组已有记忆，识别同义重复和真实纠正；明确的偏好变化可以更新原条目并保留旧版本。写入时还会核对范围、重叠内容和版本，避免旧建议覆盖新更正。对照范围有限，模型判断也可能出错，不能保证识别所有换一种说法表达的矛盾。发现错误后，不必先证明另一条结论正确，先停用即可。

意图完成或放弃后可停用，相关经验仍可单独保留。记忆不会因为年代久远自动失效，也不会替代定时提醒；是否继续使用取决于情境是否仍成立。软件版本、路径、职位等容易变化的信息，使用前应重新核对。

### 在合适的时候使用

在记忆库底部选择调用方式：

- **自动召回**：每个新回合根据当前问题和项目搜索已记住的内容，只把匹配的内容、条件和来源提供给模型。智能体也可以围绕正在调查的决定或机制进一步搜索。
- **按需召回**：不自动选择记忆；需要时明确让智能体搜索个人记忆。搜索词没有匹配时，会用本轮原问题补查，减少缩写关键词丢掉任务含义造成的遗漏。
- **关闭记忆**：停止召回和新增候选，保留已有记忆供查看。

下一回合没有自动召回时，**本轮参考** 和底部的参考数量会清除上一回合的记录。按需搜索成功后会显示新的参考结果。

修改从下一回合生效，无需重启智能体；聊天工具完成修订时，也会将实际保存的内容及版本返回给智能体。**本轮参考** 中可以展开 **为什么提供这条记忆**，检查匹配词；修改过的记忆会标明召回时的旧版本。这里记录的是给模型提供了什么，不能据此认定模型正确采用了它。自动匹配目前依赖中文和英文词项与项目范围，不能保证找到换一种说法表达的经验，也不能证明适用条件已满足。当前要求和当前核实的事实优先于历史记忆；主智能体收到的指引要求它在记忆实际改变建议时说明依据，用户仍可指出“不适用于这次”。

**编辑** 最多保留五个历史内容版本。**停用** 停止召回并保留记录；在 **已停用** 中可 **恢复**。已保存或已停用的记忆都可以直接选择 **忘记**，确认删除记忆、修订记录、待确认修订和召回引用。忽略的候选也保留在 **已停用** 中。已经包含这些内容的历史聊天不会随之删除。`Ctrl+F` 聚焦搜索，`↓` 进入列表，`Esc` 返回会话。

个人记忆保存在用户配置目录中的 `personal-memory.json`。召回的内容会随请求发送给已配置的模型服务；提炼时还会发送有长度限制的近期对话与已有记忆供比较。单次最多召回五条，渲染后的记忆内容合计不超过 6,000 字符。自动提取每次最多三条，不扫描旧会话日志，没有后台批量提炼任务。记忆库最多保存 500 条、八 MiB，达到容量时会提示。主对话智能体和 `icode run` 可以使用个人记忆；子智能体与工作流智能体不会自动获得这份私人记忆库。

## 参考文件

以下设置针对 `/agents memory` 中配置的参考文件。

## 准备记忆内容

**记忆会在主智能体加载时加入系统提示词。** iCode 会读取当前主智能体配置的记忆文件，并将内容作为参考资料提供给智能体。记忆内容会占用模型的上下文窗口，并随请求发送给模型服务。因此，建议避免在记忆中包含密钥、访问令牌等敏感信息。

**子智能体不加载记忆。** 子智能体不会继承主智能体已加载的记忆，也不会加载自身智能体配置中的记忆。[工作流](../running/workflows.md)中的智能体节点则会加载其智能体配置中的记忆。

**记忆适合保存稳定且通用的信息。** iCode 只加载扩展名为 `.md` 或 `.txt` 的记忆文件。适合放入记忆的内容应当能够在多个任务中重复使用，例如项目约定、背景资料和常用信息。内容应简短、明确并保持更新；临时任务要求更适合直接写在当前请求中。

**默认智能体已配置 AGENTS.md 作为记忆。** iCode 默认提供的主智能体（如 Code Agent）会加载工作目录中的 `AGENTS.md`。需要为项目补充通用说明时，可以优先维护该文件；如不需要，可在“记忆”标签页中删除该条目。

## 添加记忆文件

1. 在输入栏中输入 `/agents memory`，打开当前智能体的“记忆”标签页。如需配置其他主智能体，在左侧列表中选择。
2. 在“文件”区域点击“+ 添加文件”。
3. 输入路径，或通过“浏览”按钮选择 `.md` 或 `.txt` 文件。勾选“工作区相对路径”时填写相对路径（例如 `AGENTS.md`、`docs/context.md`），否则填写绝对路径。
   
    > **注意**：相对路径在加载记忆时按当前工作目录解析，而不是按照创建智能体配置时的目录解析。因此，同一个智能体可以在不同项目中加载各自的 `AGENTS.md`。相对路径不能指向工作目录以外的位置；如需加载工作目录以外的文件，请使用绝对路径。
4. 点击“保存”，然后关闭智能体配置窗口。

## 添加记忆文件夹

需要加载一组参考文件时，在“文件夹”区域点击“+ 添加文件夹”，勾选“工作区相对路径”时填写相对路径，否则填写绝对路径。添加完成后点击“保存”，然后关闭智能体配置窗口。

iCode 会先加载该目录直属的 `.md` 和 `.txt` 文件，再逐层扫描子目录。对于每个配置的文件夹，最多扫描两层子目录，最多加载 100 个文件。若某个重要文件可能不在扫描范围内，可将其单独添加到“文件”区域。

## 记忆的加载与重新加载

同一实际文件同时被单独添加和从文件夹中发现时，只会加载一次。多个记忆来源的合计内容上限为 35,000 词元。iCode 先加载单独添加的文件，再加载文件夹；一旦某个文件会使内容超过上限，该文件及其后的所有文件都会被跳过，iCode 会显示警告。

切换工作目录或修改当前智能体配置后，iCode 会根据新路径重新加载记忆。

在磁盘上修改记忆文件后，空闲时执行 `/reload`，下一次请求就会包含新正文。使用 OpenAI Responses 服务端存储时，记忆变化可能使原服务端续接失效；iCode 会提示并从本地历史继续。

## 验证记忆是否加载

在输入栏中输入 `/runtime`，或点击输入栏上方状态栏右端显示的文件数量，打开“运行时详情”窗口，切换到“文件”标签页。页面会按配置来源列出实际加载的文件。预期文件出现在列表中，即表示记忆已加载。

如果预期文件未显示，请检查：

* 路径是否存在，文件扩展名是否为 `.md` 或 `.txt`。
* 相对路径指向的文件是否位于当前工作目录内。
* 添加的条目类型与实际路径是否匹配（文件条目应指向文件，文件夹条目应指向文件夹）。
* 是否出现内容超过 35,000 词元或部分文件被跳过的警告。
* 修改配置后是否点击了“保存”。
