# 用户级个性化记忆

用户级个性化记忆，简称**个性化记忆**，保存你希望延续到以后任务的偏好、选择依据、经验和未完成意图。在相关任务中，它帮助智能体减少重复询问，沿用适用的经验，并根据你的新表达纠正旧内容。入口是 `/memory` 或会话底部的记忆入口。

可用一条示例记忆试用保存、跨会话召回和更正。[个性化记忆演示](../configuration/memory-demo.md)

## 保存前先审核

助手提议保存、但没有明确请求支撑的条目会先等你确认。底栏显示 `Mem · Save? N`，点它或输入 `/memory pending`，打开一个弹窗，逐条列出标题、全文和它引用的原话。按 `y` 或“全部保存”留下整批，按 `n` 或“全部丢弃”清掉，按 `Esc` 关闭且不做决定。你没回答之前，库里不会写入任何东西；未确认的提议 24 小时后过期，重启也会清空。

一条提议能进这个队列，需要满足几个与语言无关的条件：引用的原话出现在你最新一条消息里，不在代码块、引用块或反引号中，长度不超过 200 字，一批不超过 20 条。

## 什么值得记住

保留能在将来的具体情境中改变判断或行动的内容，并保留它成立的条件。

| 内容 | 适用范围 |
| --- | --- |
| “做技术 PPT 时，我偏好图文结合、信息密度较高的版面” | 跨项目的个人偏好 |
| “这个项目的报告未更新时，先检查持久化产物版本” | 仅当前项目的经验 |
| “这次演示只用一页纯文字” | 当前任务的临时要求，不应自动改成长久偏好 |

项目范围的条目仍属于你的私有个性化记忆库，不会自动成为团队或组织的共同规则。一次失败不能被扩写成关于你的能力、性格或某种方案的永久负面判断。

可以这样交代组合任务。「学习这些 Agent 配置，整理成文档，再把可复用的做法写入我的个性化记忆。」文档保存完整分析，记忆保留将来能直接使用的规则、适用情境和一个应用或验收例子。详情会显示分析或读取结果中的原话，供你核对依据。

已经讨论过一种做法时，也可以说「下次做同类任务时，请继续按这个方法来。」仅要求写文档时，默认按文档任务完成。开启提炼建议后，智能体发现可复用经验时可以提交待确认建议。

## 按类型、主题和情境使用

记忆是否有价值，取决于它能否在新的具体情境中帮助你判断或行动。使用频繁不等于正确，长期未用也不等于该删除。

| 类型 | 使用方式 |
| --- | --- |
| 偏好 | 默认按情境查找。明确希望持续适用的协作偏好，可在编辑器选择“始终可用”；自动召回最多带入两条，仍服从当前要求 |
| 决定 | 保留选择及理由，在再次遇到相关取舍时参考 |
| 经验 | 保留做法、成立情境及例外；从多条经验归纳的方法先待确认 |
| 意图 | 记录方向时按情境参考；需要跨会话跟进的事项，另外选择“作为待办跟进” |

`/memory` 顶部可按类型、主题和工作区筛选。列表每条显示标题，以及状态、范围、版本和更新时间；待确认、本轮参考和待办页签的数量随筛选更新。主题是简短的检索线索，例如 `PPT`、`缓存`、`发布`；标题、正文和适用情境也可搜索。“全部”显示所有工作区，聊天召回仍只读取个人与当前项目的内容。

## 跨会话待办

可以说：“帮我记住，下次发布前做一次回滚演练，下一步先在测试环境验证。”也可以新建“意图”，展开更多选项并选择“作为待办跟进”。普通任务拆解继续使用会话内 Todo；不会把 Agent 的整份计划自动变成你的长期承诺。

- **待办** 页签管理未开始、进行中、等待、稍后、已完成、已取消的事项。助手提出的下一步建议先待确认，确认后才参与提醒。
- **继续** 把事项及下一步放入输入框，按 Enter 后才开始执行；已有草稿会保留。**标记完成** 停止后续提醒，仍可查看记录。其他状态和提醒时间在编辑器中修改。
- 提醒时间未写时区时按本机时间处理。自动召回最多带入一条到期事项；没有时间的事项按当前任务相关性找到。等待状态不表示可以自动开始行动。
- “稍后”在设定时间前不参与召回。完成和取消后不再自动提醒；需要再次推进时，可明确改回待办状态。

提醒在使用 iCode 时显示。关闭应用期间没有独立通知或定时执行进程。Buddy 没有本轮参考时，可展示一条已到期事项，点击进入详情；不会自动打开弹窗。

## 把经验整理成方法

可以要求：“找出与 IR 设计有关的经验，整理成可复用的方法，保留适用条件和例外。”智能体先检查现有条目，再关联它们：支持、例外、归纳来源或合并来源都会记录理由与源版本。

新归纳的方法始终进入**待确认**。详情中的“关联依据”可核对来源；确认后，相关经验被找到时，也可以带出关联的方法。关联只展开一层，与其他记忆共享单次五条和 6,000 字符预算。

“关联依据”只在已建立关联的条目中出现，展示关系、来源版本和理由，点击来源标题可打开原条目。主题相同会帮助检索，但不会自动建立支持或因果关系；当前没有自动生成的关系图。

可以先选中条目或主题，再点 **复盘整理**，将请求放入输入框，确认后提交。智能体会检查相关条目；按 ID 检查时还可读取预算内的旧修订。合并提案说明每条来源贡献了什么、保留哪些条件，原条目继续生效。你在 `/memory` 启用提案，或在后续消息中确认后，才一次性合并并归档来源；任一来源版本改变，整次确认都会被拒绝，需要重新审查。独立待办不会作为事实合并。

来源被修改、停用或版本不再一致时，派生方法暂不参与召回，详情提示需要重新审查。可要求智能体根据最新来源重新整理；只修改方法的文字不会刷新它的来源版本。合并只适用于同范围、同类型的已生效条目，不合并独立待办；任何来源版本冲突都会拒绝整次合并。

## 看见使用效果

“本轮参考”表示提供给了智能体。智能体可用工具记录哪条记忆实际改变了建议，这仍是智能体的自述。只有你明确指出“这条有帮助”或“这条不对”，才会记录为用户反馈。

- **这次不用**：本回合再次检索也排除它，下一回合重新判断，不改写长期偏好。
- **有帮助**：记录你的肯定及对应版本，不自动提高可信度或把同次回答的全部记忆一起加分。
- **错误**：记录你的纠正并停用该条，阻止继续召回；可编辑后恢复，或忘记。

条目详情显示自己的活动记录，**活动** 页签显示最近的建立、更新、提供、声明采用、反馈与待办变更。完整本地活动保存在记忆库旁的 `personal-memory.activity.jsonl`，包含顺序号、版本和可用的会话/回合依据，可用于后续个人轨迹分析。默认显示最近 128 条活动，更早记录可分页查看；完整日志不会因此截断。旧版本没有记录过的采用或反馈不会被补造。

## 开始使用

输入 `/memory`，在底部选择保存方式：

- **明确要求才保存**是默认方式。可以说“把这次提炼的做法写入个人记忆”，也可以明确下次如何沿用。
- **自动记住明确偏好**：智能体在对话中识别到明确的稳定偏好时，通过记忆工具保存并生效；推断出的习惯或经验先进入待确认。
- **全部先确认**：智能体识别出的可复用内容先进入待确认；你明确要求直接保存时仍直接保存。

原来已经开启“提炼建议”的设置会按“自动记住明确偏好”读取。普通任务不会额外调用提炼模型。实际保存后提示 **已记住：标题**，候选提示 **待确认记忆：标题**。智能体负责理解和润色，工具校验来源及版本后写入。已开启提炼建议时，实际发生的上下文压缩也可以带出待确认建议，规则见下文。

也可以点 **+ 记一条**，输入内容后按 `Ctrl+Enter` 保存。默认仅当前项目，取消该选项后可跨项目使用。

## 对话中的工具摘要

记忆调用沿用对话中现有的工具组和过程折叠，点击展开即可查看参数和结果。执行时显示“查找记忆”“整理记忆：标题”或“停用记忆”；完成后，单次调用显示实际结果，例如“已保存记忆”“待确认记忆”“记忆未变”。查找只表示查询过记忆，不代表回答已经采用它。

多次调用按记忆查找、写入请求、停用请求分别计数，失败和中断保持可见。过程折叠与重新打开会话时使用相同的摘要。没有保存回执的旧记录只显示中性的处理结果。

## 从上下文压缩保留建议

选择“自动记住明确偏好”或“全部先确认”时，上下文压缩可以利用已经进行的摘要分析，顺带提出最多两条个人记忆建议。不会为此额外请求提炼模型，也不会为了提取记忆提前触发压缩。

- 适用于智能体提交的上下文摘要，以及当前任务压缩生成的进度摘要。程序直接截取和拼接的摘要不产生建议。
- 只接收能在本次压缩的原始用户消息中核对到原话、具有明确未来用途的个人内容。项目细节、任务进度、临时要求和助手推测不应成为个人记忆。
- 摘要成功生成还不算保存。压缩提交后才写入**待确认**，保留来源会话、原始消息和引用；即使开启“自动记住明确偏好”，压缩建议也不会直接生效或覆盖原记忆。
- 同一来源的重复建议不会反复新增；已停用条目不会因再次压缩恢复。与现有生效条目直接冲突的建议不会覆盖它，可通过对话修订或记忆编辑器处理。
- 选择“明确要求才保存”或关闭记忆后，不再从压缩写入建议。摘要没有合适内容、原话无法核对或建议格式不完整时，正常保留任务摘要，不反复重试提炼。

有建议时仍使用“待确认记忆”提示，可以从 `/memory` 或 Buddy 的待确认入口检查、启用或停用。模型可能遗漏有价值的内容，也可能判断不准；明确希望保留时，直接说“帮我记住……”更可靠。

## 自然表达、润色和更新

`/memory add <文本>` 由你自己写一条：命令本身就是确认，系统不再从措辞里推测意图。第一句作为标题，你输入的原文作为内容，长度不超过 600 字。适合想立刻存下一条，或者助手提议的保存被拒绝、你更愿意用自己的话重写的情况。只输入 `/memory` 仍然打开记忆库。

助手提议保存、而你没有明确要求时，系统不会写入：底栏显示 `记忆 · 待存 N`，这条提议等你处理。`/memory confirm` 保存全部待确认的条目，`/memory decline` 全部丢弃；两条命令都可以带上 ID 只处理一条。提议 24 小时后过期，重启会话也会清空。

可以先表达偏好，再说“润色后帮我记住这条偏好”，不必重复原话。润色通常整理成一两句能独立理解的内容；来源原话单独保留。助手之前补充的建议不等于你已经确认的偏好，不应擅自添加禁令、例外或“已验证”的效果。

开启偏好保存后，表达明确的长期变化，例如“以后技术 PPT 的信息密度改成适中”，智能体可以通过工具修订原条目，不要求使用固定句式。选择“明确要求才保存”时，也可以说“下次也照这个习惯来”。写前会检查相关的生效、待确认和停用条目；智能体应复用同义条目；工具对相同内容的重复写入不新增、不刷新时间。补充经验时沿用原 ID，保留仍成立的条件；待审修订在确认前不覆盖原记忆。写入期间条目发生变化时，需要重新检查。

如果你明确说某条经验已经不适用，或一个长期目标已经完成，智能体可通过工具停用它并记录你的原话。停用保留内容和历史，之后不再召回；可在 `/memory` 恢复。单次例外、时间久远或召回次数少，不会自动导致淘汰。条件是否仍成立由智能体结合当前证据判断，语义误判仍可通过修订和停用纠正。

判断仍可能出错。保存提示出现后，可在 `/memory` 检查实际内容、个人或项目范围、来源和版本。

保存尝试被拒绝时，底栏显示 **记忆 · 未保存**；悬停可查看尝试保存的标题、简要原因和处理入口，工具结果保留详细原因。同一回合中相同标题、相同原因的重复失败不会重复提示，保存成功后清除。证据可以引用当前上下文中仍然可见的早期原话，不再局限最近 16 条消息；已经被压缩移出的原文不会被猜测或补造。

## 召回记录能说明什么

在 **本轮参考** 中，可以查看提供给模型的条目、版本、匹配词、检索依据和来源。检索依据会区分记忆 ID、标题、关键词、关联术语、相近拼写和前一任务的续接。记录仅保留有限数量会话的最近召回情况，不是逐轮保存的完整使用历史。

**L0 常驻**提供你明确选择始终可用的偏好和至多一条到期待办。**L1 开场**查找当前任务。明确提出回滚检查、预发环境核对等独立事项时，各自检索和排序，共用上下文预算。**L2 行动前补查**在本地工具执行前查看目标文件、命令的输出参数等具体线索。同一动作的普通正文修改复用检查。同一路径的交付形式发生变化时，可以重新检查。查询没有找到新依据时，召回记录和补充次数保持原样。每回合最多两次 L2 补充，按需模式和关闭模式跳过 L2。**L3 主动查询**由智能体在决定格式、做法或风险处理前调用，同一决定可以加上至多两种检索说法，共用一次补充次数。详情会显示召回阶段。

文件名和代码标识符也可以作为线索：例如 `retry_policy.py`、`RetryPolicy` 可以找到适用于“retry policy”的记忆，反向查询也适用。完整名称仍可匹配，`C++`、`C#`、`.NET` 保持区分；这不等于能理解所有语义改写。证据版本已失效的派生记忆、已完成或暂缓的待办，以及本轮排除的条目，不会占用有效记忆的候选名额。

补查找到与当前动作相关的新依据时，该批本地变更会暂缓执行。例如，生成 PowerPoint 文件可以带出排版偏好。读取 PowerPoint 源文件或仅在正文中提到该格式会直接继续。工具结果会说明动作尚未执行，并提供相关记忆。智能体判断适用条件后再决定如何发起操作，重新发起的操作仍走原有审批。并行调用只提供一份完整记忆。已提供的版本在筛选相关性之后去重，避免重复提供。

例如，用户只说“修复启动失败”，智能体准备修改 `.bashrc` 时，可以补查到“改 shell 配置前先说明影响范围”，先解释再修改。补查使用有限的本地词法检索，检查本地可控动作。暂缓执行会增加一次主模型交互来重新决定动作。L1 或 L3 有与任务相关的结果时，可以在同一预算内补充关联依据或例外。常驻偏好和到期待办按各自用途提供。

| 你关心的问题 | 当前能力 |
| --- | --- |
| 哪些记忆被提供给模型，为什么选中？ | 可以在本轮参考查看 |
| 模型实际采用了哪条，改变了哪项建议？ | 可以记录智能体的采用声明和理由；不能仅由“被召回”推出，也不能独立证明实际收益 |
| 用户肯定或否定了这条记忆带来的效果吗？ | 区分“效果未知”“本轮不适用”和“记忆有误”；明确反馈关联到条目和版本，不从沉默或智能体自报采用推断收益 |
| 能根据新的表达纠正旧内容吗？ | 可以识别明确的偏好变化或保存、更新意图；不是完整的效果归因 |
| 能停用无效、过时的记忆吗？ | 用户明确说明失效或意图完成时，智能体可通过工具停用并记录原因；不按年龄、低频或笼统评价淘汰，删除仍需在记忆库中确认 |

检索先限定个人或当前项目的已生效条目，再结合标题、适用情境、关键词和常用中英文术语选择。例如，“PowerPoint”“幻灯片”“演示文稿”可以找到 PPT 偏好；单独的“用户”“效果”等泛词不再作为依据。适用情境中限定为 PPT 的偏好，不会仅因网页任务也提到“图文结合”就自动召回。

你可以要求“查一下记忆 `<ID>`”或使用标题查找具体条目。ID 可使用至少八位、且在当前可用范围内唯一的前缀。明显的英文拼写偏差也有有限的查找兜底。“继续”等明确的短句会参考最近的用户任务；提出新任务时，不沿用上个任务的主题。

这些规则改善了术语变化和短句造成的遗漏，但并不理解所有同义表达或隐含条件。找不到时，可以补充标题、任务主题或适用情境；发现误召回时，先检查情境是否写得准确。某条记忆被用在错误场景，不证明它本身没有价值。

在 **编辑 → 更多选项** 中，可以给条目补充最多六个常用检索说法，保存后即可用于查找。记忆库搜索也复用术语、拼写兜底，按已选择的类型、状态和工作区展示结果，不受智能体单次五条的限制。普通任务中的 commit hash 不会仅因撞上 ID 就触发自动召回，明确的“记忆 `<ID>`”查找仍有效。长问题在相同字符预算内保留首尾，减少末尾任务要求被截掉的遗漏。

自动召回会去除明显弱于本次最佳匹配的条目，不为凑满数量而填入宽泛相关的内容。按需检索保留较宽的相关结果，便于主动查找和检查。

用户说“很好”，不能证明所有被召回的记忆都有帮助；没有反对也不等于认可。一次回答不好，同样不足以把问题归因到某条记忆。当前系统不会据此自动累加可靠性分数、调整召回排序或淘汰条目。

## Buddy 中的个性化记忆

已有 Buddy 时，打开侧栏的 **伙伴（Buddy）** 页签，等级下方会显示本次参考的记忆标题和正文摘要。侧栏隐藏时按 `Ctrl+G` 打开；尚未创建 Buddy 时可使用 `/buddy hatch`，也可以继续通过 `/memory` 使用全部记忆管理功能。

- 用 **‹ / ›** 翻看本轮参考；中间的页码可打开完整列表。状态刷新保留当前翻到的条目，新任务的召回重新从第一条开始。
- 点击正文打开该条详情；悬停可以阅读完整内容。没有本轮参考时，优先展示一条到期事项。相关记忆积累、跨会话纠正重复出现或有条目需要审查时，可以出现本周回顾；候选不再常驻占用角标和预览。
- **已记住** 显示当前项目可用的生效条目数；**回顾** 进入周摘要关联的队列：成员确实需要整理时打开 **待整理**，否则沿用候选或原先的视图；打开后收起本次摘要。窄侧栏用符号和数量，悬停显示完整名称。候选随时可在 `/memory` 查看。
- **○ / ● 提醒** 同时控制召回提示与周摘要，默认关闭。周摘要在自然使用时产生，七天内最多一次，不运行后台分析模型或通知进程。同一主题积累三条记忆、同类纠正跨三个会话出现时，可建议复盘；这不代表已证实某种稳定习惯。重复刷新和查看记忆库不会再生成一份。Buddy 静音时也不主动播报。
- 鼠标点击不会留下行选中效果，也不会触发抚摸 Buddy；键盘可用 `Tab` 移动焦点、`Enter` 翻页或打开。

看板不会自动切换页签或打开弹窗。它显示的是提供给智能体的参考，不代表回答已经采用，更不代表效果已经得到验证。修改、停用或删除记忆后，看板不再把旧召回记录显示成当前版本的参考。关闭记忆后不显示本轮参考，待确认建议仍可以管理。

## 如何反馈和纠偏

| 情况 | 可以怎样处理 |
| --- | --- |
| 这次不适用，但长期偏好仍成立 | 说明“仅这次不适用”。当前要求优先，不应据此改写长期偏好 |
| 原来记错了，或长期偏好已经改变 | 说清正确内容和适用范围，检查是否修订了原条目 |
| 内容有效，但被用在了错误场景 | 在编辑器中收紧 **适用情境**；不要仅因一次误召回就删除有效经验 |
| 暂时不能再使用，又不确定如何改正 | 说明哪条记忆不应继续使用，检查工具是否确认停用；也可在 `/memory` 点 **停用** |
| 明确不需要保留 | 点 **忘记** 并确认删除 |
| 这次有效，希望保留具体经验 | 明确说明什么做法在什么条件下有效，再要求保存或更新；笼统赞同不会自动强化所有记忆 |

停用的条目停止参与后续召回，可以恢复。忘记会删除条目及相关修订、待审修订、召回引用和本地活动内容；依赖它归纳或合并出的内容也会删除。忘记不会擦除已有聊天记录。清理失败会报告未完成，可重试。长期未使用不等于无价值，条目不会仅因年代久远自动过期。

## 标题、召回视图与写入记录

标题只写主题，不写句子：超过 40 字、以句末标点结尾或含逗号分句的标题会被拒绝。请 iCode 改名时只改标题，正文、来源和修订历史都保留，版本号加一。

智能体写入前查看相关条目时，默认拿到的是索引：编号、标题、版本、状态、主题和适用情境。只有显式要求完整视图时，才返回正文和历史修订。查看过一次之后可以连续写入多条，不必每次重新召回；替换某条记忆前，必须先查看过它当前的版本。

智能体提议的写入不会自行入库。没有明确请求的保存会停在底栏等你确认或丢弃，结果分别记为 `memory.save.committed`、`memory.save.rejected`、`memory.recall.served` 或 `memory.consent.resolved` 写入会话轨迹，只含计数和错误码，不含标题和正文。确认写入的来源记为 `consent`，历史里能区分"你点了确认"和"你自己用 `/memory add` 写的"。

待确认的提议只存在于当前进程：重启或换会话都不会带过去，所以弹窗列的只是本会话提出来的那些。

## 审核与维护

搜索会在短暂停顿后更新，按 `Enter` 可立即进入结果。详情中的关联条目可直接打开，当前的类型、主题或范围筛选不会挡住跳转。编辑器中的字段名称始终可见，填写错误显示在保存按钮上方，并定位到相应字段。主题最多六个（每项 1–40 字符），检索说法最多六条（每条 2–80 字符）。

打开面板后焦点落在列表：`↑/↓` 移动，`Enter` 进入详情，`Tab / Shift+Tab` 切换控件，`Ctrl+F` 搜索。搜索框中按 `Esc` 先清空搜索，再按回到列表；详情中按 `Esc` 回到列表，列表中再按关闭。`Delete` 打开忘记确认，不会直接删除；`Ctrl+N` 新建，`Ctrl+R` 刷新。

**何时不再适用** 填写这条记忆不能继续直接套用的条件。例如“技术 PPT 偏好高密度图形化表达”，可以补充“远距离投影、面向非技术听众时应降低密度”。遇到这些情况应核实或更新旧偏好，不会自动删除记忆；没有明确条件时可以留空。

换标题、主题或检索说法不会把同一个事实变成新记忆。需要调整这些内容时，编辑原条目；通过聊天再次提案时，已停用的事实必须通过原条目的 **恢复** 重新启用。

- 在列表中点 **选择** 或按 `Space` 标记条目，再批量记住、停用或忘记。按 `Esc` 或点 **退出多选** 清空全部勾选并保留当前位置；切换页签也退出多选。单次最多 25 条，提交前核对全部版本；其中一条被其他会话改过，就拒绝整批操作。待审的替代建议不会阻止你更正已生效条目。同标题、同情境的重复候选需要先处理原候选。
- 记忆库显示条目数和文件大小，取消条数配额；底栏复核提醒涵盖待复审、内容重复和多次不适用的条目，点击进入 **待整理**。文件仍有 64 MiB 完整性保护上限。最近一份旧修订可直接查看，**更早修订** 按需读取完整历史；旧版修订先保留再精简，迁移中断可继续。
- 详情按当前版本最近五个有记录的召回回合，分别统计提供、智能体自报采用、用户跳过和智能体跳过。明确的有帮助反馈单独统计，也接收其他会话的反馈。至少三个不同召回回合被跳过时提醒检查适用情境。统计基于近期保留的活动，可能缺少更早记录，不是可信度评分；有记录时显示最近召回日期，不把时间久远当作失效。
- 即使换了会话，也可以对当前展示的已生效版本点 **有帮助** 或 **有误**。**本轮不适用** 仍要求本轮确实提供过这个版本。旧版本的记录可在活动历史中查看，不会被记到新版本名下。
- **活动 → 更早活动** 每页读取完整本地日志中的 100 条记录；**最新** 回到近期。读取时显示加载状态，翻页按钮暂时不可用，仍可切换页签或按 `Esc` 关闭。新页从顶部显示；读取失败保留当前页。新增记录、编辑和召回不会打断旧页阅读；忘记操作会清除可能含已删除内容的旧页。
- 支持、例外以及归纳关系引用的来源发生修订或停用后，关联条目暂停召回，重新检查关系后再使用。已完成、已取消的待办需要明确重新开启为 **待办**，之后才能继续变更进度。

如果一次操作需要改动过多关联条目，系统会拒绝整次操作并保留原库。批量操作可减少本次选择后重试。单条记忆如果关联了大量仍需保留的条目，也可能遇到此限制；当前界面尚无批量解除关联的入口。

**待复审** 表示当前版本在三个不同回合被你明确标记“本轮不适用”，条目继续生效，并会出现在 **待整理** 中，便于收窄适用条件。若三次针对同一个规范化查询和工作区，之后只抑制该情境的自动召回，其他情境和显式查询仍可找到；它不尝试把所有语义相近的场景一并排除。你可以编辑条件，或选择 **保留条件** 清除这些检索排除记录。新内容版本重新积累依据。

### 待整理

**待整理** 是唯一的复核队列。它列出未归档、且满足以下任一原因的条目：同类型同范围内内容相同（忽略大小写、全半角和空白差异）、来源已变化或已停用、当前版本反复收到“本轮不适用”反馈、已标记需复核。一条记忆命中多个原因时只出现一行，详情列出全部适用原因；内容重复的详情逐个给出同组条目的标题或 ID（包括被当前筛选隐藏的伙伴），不会引用其他工作区。时间久远、很少召回、沉默、仅被提供、仅智能体跳过、仅候选状态、仅周摘要分组、仅被筛选隐藏都不是原因。

视图遵守当前工作区、个人/项目范围、类型、主题和搜索过滤。原因按完整记忆库判定，筛选只隐藏行，不会抹掉原因。按现有方式勾选，单次最多 25 条；只有当条目仍在当前过滤后的队列中且版本未变时才保留勾选，筛选变化、刷新或版本变化会移除勾选，恢复筛选也不会恢复。浏览、筛选和选择不会写入记忆库；切换页签仍会清空勾选。

点 **复盘整理** 会把所选条目的 ID 和版本放入输入框，按 Enter 才会发送。没有选择但有主题筛选或搜索内容时，请求只带该上下文，不含任何 ID；两者都没有时提示先选择记忆或主题，面板保持打开。草稿无法替换时保留面板、草稿和勾选。智能体只提出归纳或合并建议，合并或停用仍需你确认。

空视图会分别说明“没有需要整理的记忆”或“没有符合当前筛选的待整理记忆”，两者都不表示记忆库为空或内容被删除。

页脚复核提醒会打开 **待整理**；Buddy 的 **回顾** 入口在本次周摘要成员确实需要整理时也会打开它。仅有来源已变化时，页脚保持普通浏览目标。**已记住**、页码、条目点击以及 `/memory` 的已记住/回顾/本轮/待办/活动/已暂停/全部页签都不会因为过去的周摘要或当前待整理项改道。

三种结果分别处理：**效果未知** 表示没有本次使用的明确反馈，即使用过多次也不会因此停用；**本轮不适用** 排除本轮召回，智能体自行报告跳过只保留记录，不训练你的长期偏好；**记忆有误** 需要你的明确纠正，立即停用并保留原话与历史，修订或恢复后才再次使用。旧策略仅因缺少反馈或重复跳过而自动转入待复审的条目，会在维护时恢复；你明确停用的条目不会恢复。候选超过 30 天未审仍会自动归档，之后可查看或恢复。大批维护保留每条活动记录，中断后下次访问继续。

写入内容若与同一情境下的已有事实高度近似，拒绝信息会指出原条目：可以按原 ID 修订，或说清不同的适用情境再另存。系统不会静默合并不同主张。

保存成功会清除“未保存”提示，重复确认同一内容不会重复弹出保存通知。召回不可用时，底栏显示 **记忆 · 不可用**，成功读取后恢复；行动补查失败会保留正常工具执行能力。持续不可用时只提示一次，恢复后再次出错会重新提示。批量操作提交期间按钮暂时锁定；失败时保留勾选，处理原因后可重试。刷新后，已被修改的条目会取消勾选，核对新内容后可重新选择。

无界面运行通过原有 stderr 进度显示保存和拒绝回执；`icode run --json` 不提供这些进度回执。ACP 客户端可根据声明的能力订阅 `chrys/personal_memory` 扩展通知，收到本次保存条目的 ID、版本、状态和标题，或拒绝代码与原因，不发送整个私人记忆库。候选管理仍使用 `/memory`。

## 与其他记忆机制的区别

| 机制 | 入口与用途 |
| --- | --- |
| **个性化记忆** | `/memory`：保存你的偏好和有条件的经验，按任务选择相关条目，支持来源检查、修订、停用和忘记 |
| **智能体的记忆文件配置** | `/agents memory`：为智能体加载 `AGENTS.md`、Markdown 或文本参考文件；由文件内容及配置决定，不等于系统抽取了你的个人偏好 |
| **上下文压缩摘要** | 帮助当前会话延续任务；摘要不会自动变成已确认的长期个性化记忆 |

本指南中的“个性化记忆”专指第一项。记忆文件的添加和加载操作见[记忆文件配置](../configuration/memory.md#添加记忆文件)。某份资料被加载、某句话被重复摘要，都不能单独增加一条个人偏好的可信度。

## 调用方式与成本

**自动召回** 根据当前问题和项目选择记忆；**按需召回** 需要你要求查找；**关闭记忆** 停止聊天中的读取和写入，记忆库编辑器仍可使用。只选择“明确要求才保存”会关闭自动提取，不会关闭自动召回。

写入由主智能体按需调用记忆工具，不再逐回合运行独立提炼请求，工具内部也不调用第二个模型。普通任务的本地召回仍然保留；识别偏好与润色会使用主智能体的正常推理，写入和查重有普通工具调用成本。聊天写入的普通正文最多 600 字符。经验附有具体应用或验收例子时，正文和例子合计最多 1,600 字符。单次召回最多五条、6,000 渲染字符；每回合最多三次补充检索，L2 只有发现新记忆才占次数，至多占两次，为主动查询保留一次次数预算；没有结果的本地候选检查不计次。各层累计最多提供 15 个不同条目、18,000 渲染字符，重复提供的同版本记忆不重复计入自动召回字符预算。写前检查使用独立的八条、12,000 字符候选列表，仅供对比，不代表已经检查完整个记忆库。模型可能漏识别，明确提出保存要求或使用编辑器可补充保存。

本地检索和 Buddy 提醒不调用提炼模型；行动暂缓后，主智能体需要重新判断再发起操作。重复查询使用本地热缓存；修改、停用或忘记条目后，后续查询使用最新内容，其他实例的修改也会使缓存失效。相同证据的不同说法不会被作为多份依据重复加分；缓存命中或使用频繁本身不会增加一条记忆的可信度。

召回记录与主库分开保存，普通检索不再重写全部条目；多窗口下仍核对更正、删除、复审与召回的版本一致性。自动召回只使用当前生效内容，显式检查也可查看待确认、停用和待整理材料。

已有第 1–3 版记忆库可读取；更新时升级为第 4 版，保留检索说法、回合预算与审查依据。多个本地分支共用这份库，升级后应使用兼容版本。备份或迁移时，请一起保留 `personal-memory.json`、`personal-memory.recalls.json` 和 `personal-memory.activity.jsonl`；记录与主库版本不匹配时会报告问题，不会静默覆盖历史。已有意图不会因升级自动变成待办。

记忆保存在本地；被召回或为写入而检查的条目会发送给已配置的主模型，待确认和停用内容仅供对比，不作为已生效建议。不会扫描全部旧会话或运行后台批量提炼。当前主对话智能体可以使用个性化记忆，子智能体和工作流智能体不会自动获得这份私人记忆库。
