# 个性化记忆：开发任务与验收记录

本轮目标：让类型影响记忆使用，记录建立和使用过程，支持跨会话未完成事项及基于证据的关联整理，并在现有 `/memory` 与 Buddy 内可见、可管理。保留现有主 Agent 工具写入及压缩候选策略，不新增每回合提炼，不修改原记忆配置指南。

本文供开发和验收跟踪使用；用户说明更新在中英文 `daily-use/personalized-memory.md`。

## 任务顺序

- [x] 1. 类型与历史：兼容现有库，支持用户确认的常用偏好、主题与类型筛选；记录带版本/会话/回合依据的变更、召回及反馈，支持本次不采用；删除同步清理派生引用。
- [x] 2. 跨会话事项：明确意图的未完成、等待、延期、完成、取消状态；场景/到期提醒；明确用户要求才启用事项，Agent 建议保留候选；复用原有会话任务入口承接执行，避免复制整份 Todo。
- [x] 3. 关联与整理：有理由、有版本依据的支持/例外/派生关系；按需读取关联；方法归纳候选关联原条目，来源变化可见；原子合并保留来源，拒绝旧版本覆盖。
- [x] 4. 用户入口：现有记忆窗口提供本次、分类/主题/范围、待办与历史；可用键盘进行反馈、状态更新和关联审核；Buddy 提供简洁的相关事项入口。
- [x] 5. 行为验证：存储迁移/并发/删除、工具授权和真实引擎调用、跨会话提醒、候选不生效、TUI `/memory` 入口和窄终端操作；执行 Smart Test 及独立质量检查，记录扩大回归未全绿的限制。

## 必须成立的边界

- 普通任务没有额外提炼模型调用；模型推断不能自动成为用户承诺或方法论。
- 频次不决定真实性或自动淘汰；本次不适用与永久停用分开。
- 记忆 ID/版本与原始来源可追溯；重复摘要不形成独立证据。
- 提供给模型、模型声明采用、用户反馈分别记录，不能把它们统称为有效。
- 待办的状态只由明确操作更新；没有持久调度进程时，日期提醒在使用应用时呈现，不承诺离线推送。
- 按需关联与方法候选使用已有主 Agent，不引入后台知识图谱或反思服务。
- 用户私有项目范围不变成组织共享权限。

## 验收结果

本轮保留既有未提交改动，以修改前文件散列确定自己的 36 条修改路径。原记忆配置指南未修改。本轮没有新增依赖、后台提炼进程或向真实个人库写入测试数据。

核心原则：记忆的作用是让有证据、带条件的既往经验和未完成意图改善下一次行动。类型决定处理方式，来源版本决定能否沿用；提供、声明采用、用户反馈分别留痕，不合成为未经验证的价值分数。

已完成的定向验证：

- 最终功能回归 226 项通过：完整记忆专项、版本化派生、来源纠正与删除、日志故障恢复、到期/稍后/完成、跨项目隔离、自然语言证据、真实 `/memory` 入口，以及主/子智能体工具隔离和翻译目录检查。
- 真实引擎通过 MockChatClient 执行 review_memory 和 update_follow_up，保存可归属到回合的采用声明及完成状态；普通任务测试仍只有主模型调用。该结果验证调用和数据路径，不证明真实模型的识别率或长期收益。
- 60、80、120 列的筛选、临时排除、完成和活动查看通过。继续事项保留原草稿，填入输入框但不自动提交；测试等待原生按钮点击动画结束后再触发第二次操作。
- v1 旧库读取不改文件，下次写入升级 v2，原 ID 和意图含义保留。旧版本客户端不支持 v2，应避免混用。
- 故障复现发现超长来源元数据会造成记忆已提交、活动日志无法追加，进而阻塞后续保存。已改为提交前验证活动记录大小；回归验证原文件不变、随后正常保存成功、日志没有半条记录。

500 条合成记忆的本机性能试验（Windows / Python 3.14.8，热读等每组 30 次，未清操作系统缓存）：最终热读 P95 为 11.785 ms（无历史版本）和 6.936 ms（每条 5 个历史版本）；包含召回记录持久化分别为 190.103 ms 和 725.711 ms。新实例 P95 分别为 235.451 ms 和 401.081 ms；索引保留内存约 2.38 MB。更早的同机试验曾测得热读 P95 约 1.8–2.0 ms，说明这些本地耗时存在明显波动，不应把最好的单次结果当成承诺。

初测发现重复建立关联查找映射，已改为复用单次查询映射。持久化仍需重写带历史版本的有限 JSON 快照，远比纯检索昂贵；操作已放到工作线程，但该成本仍会增加提供记忆前的等待。当前没有针对高频写入引入数据库或分拆存储。这些数据用于排查本机开销，不证明模型召回质量或线上 SLA。
