# 个性化记忆评审处理记录

本轮依据用户提供的《用户级个性化记忆功能评审报告》核对当前分支，并修复已确认的问题。保留原分支的未提交功能；不修改原有记忆文件配置文档。验收输出是功能改动、行为回归测试，以及这份逐项处理说明。

## 处理结果与边界

| 评审项 | 处理 |
| --- | --- |
| C1 / C2：默认不保存、经验需要审核 | 保持此前明确选择的策略。启用自动偏好保存仍只允许明确的持久偏好，推断经验需要确认；提供批量审核降低维护成本。未擅自打开自动保存。 |
| C3 / C5：写入被拒绝但用户不知道 | 每次 `propose_memory` 拒绝产生带标题和原因代码的事件。底栏持续显示未保存，悬停给出处理办法；同回合同标题同原因去重，成功后清除。写前检查门仍保留。 |
| C4：较早的偏好被证据窗口丢弃 | 核对全部仍可见的对话原文，移除最近 16 条和每条 12,000 字符截断。未扫描磁盘旧会话，也不伪造压缩后已不存在的原话。压缩产出仍只能创建经原文核对的候选。 |
| R1：同义表达漏召回 | 增加条目专用检索说法，最多六个；编辑器和工具都能维护，随修订刷新索引。管理界面复用术语和拼写检索，保留子串查找，不套用五条召回上限。仍不是任意改写的语义检索。 |
| R2：按需模式没有自动注入 | 这是用户选择的模式含义，保持不变，指南已明确。 |
| R3：自动路径需要再查用户原句 | 源码不支持该判断：`prepare` 已从最新用户原句取查询。没有重复同一搜索。真正存在的长输入末尾被截断问题已修复，同一 4,000 字符预算保留首尾。手动关键词补查与主查询共用一次计数。 |
| R4：续接窄、八回合后失忆 | 支持“继续写下一节”等明确续接，向仍可见的最近实质用户输入回溯，不再限八条。遇到新任务或话题切换就停；不把任意“继续 + 新主题”解释为沿用旧任务。 |
| R5：子智能体不读私人库 | 保留隔离。只读共享需要明确受众、权限和工作流传播规则，未作为缺陷修复直接开启。 |
| R6：每轮提示过长 | 压缩常驻指引，具体参数约束由工具定义承载；仍保留当前要求优先、候选审核、来源、范围和失败回执规则。 |
| R7：commit hash 触发记忆 ID 直通 | 自动检索只有独立 ID 或明确 `memory/记忆 <ID>` 才享受直通；工具中的明确查找保留唯一前缀能力。普通文本仍可因实际内容相关而命中，不再仅凭 hash 强推。 |
| 管理：批量、容量、日志、库内搜索、反馈消失 | 已加入最多 25 条的原子批量审核/停用/忘记、条目和字节占用、450 条或 85% 容量提醒、完整活动日志的 100 条分页、复用检索索引。当前版本的有帮助/有误反馈不再依赖本会话召回；本轮排除仍校验确切版本。 |
| Q1：查重只查 active，inspect 过窄 | 同标题同情境的重复候选会给出原 ID 和版本，要求检查；待审建议不会阻塞用户更正 active。比较窗口独立为八条/12,000 字符，并明确是候选列表，不能声称看完全部。语义冲突仍由主智能体和审核者判断。 |
| Q2 / Q3：模型把临时表述说成持久结论 | 保留模型语义判断及候选复核，补齐远距离否定和单引号例子的授权防护；完全在引用中的偏好不免审激活。逐字核验不能证明持久性，未声称解决全部语义误判。 |
| Q4 / Q5：反馈和年龄不可见 | 详情区分别显示召回、智能体自报采用、用户有帮助反馈及两类跳过。召回最多取近期五个有记录的回合，跨回合三次跳过提示检查情境；显示可获得的最近召回日期。不推导可信度、不因低频或老旧删除。近期记录截断的限制在指南中明确。 |
| Q6：关联证据更新后照常召回 | 支持、例外、归纳、合并关系均核对版本；除合并来源允许保留归档外，其他来源必须有效。来源修订或停用后依赖条目停止召回，仍可检查修订。 |
| Q7：applied 是模型自报 | 继续明确区分“已提供”“智能体自报采用”和“明确有帮助”；没有可靠方法仅从回复自动证明真实效果，未给自报加可信度分。 |
| Q8：已结束待办任意跳转 | 已完成/已取消仅能明确重开为 pending，再继续变更进度。主工具需要 reopen=true，编辑器中的主动选择视为用户操作；通用保存路径同样检查，避免绕过。 |
| 单回合无总预算 | 一回合最多三次额外工具查询、15 个不同条目、18,000 渲染字符；单次五条/6,000。限额在锁内持久化，重建 runtime 不重置；自动重复准备只复用已提供版本，新的版本/内容仍计费。写前检查不占建议预算。 |
| ACP / headless 无表面 | 主会话事件流接入记忆事件，CLI 使用原有 stderr 进度，ACP 发送 `chrys/personal_memory` 的本次操作回执。不会序列化整个库。ACP 管理命令尚未新增。 |
| 验证中新发现：大量关联清理截断未提交日志 | 忘记一个来源可能连带修订超过 128 条支持/例外关联，原实现会先写库，再发现 outbox 已截断，导致日志缺口和后续写入阻塞。现在提交前检查新事件是否完整，超限就整次拒绝，库和日志保持不变。批量操作可以减少选择；单个来源的关联数量过多时仍有删除限制，界面尚无批量解除关联入口。这里完成的是数据完整性修复，未声称消除所有操作数量限制。 |

## 未直接并入的产品扩展

- 本地 ONNX 嵌入、嵌入查重不是小修补，需要确定模型分发及固定版本、许可、资源占用、召回质量基线和失效重建策略。当前没有新增模型、远程嵌入 API、向量库或运行依赖。
- 子智能体共享、ACP 管理命令、备份导入导出、主设置页的发现入口仍是独立扩展。这轮未将其标为已实现。现有 toast 组件不支持操作按钮，使用原有底栏/候选列表入口和批量审核，未重写通知框架。
- 反馈数据用于检查和纠偏，不自动调整可信度或排序。任意语义改写召回、跨版本历史反馈交互、无限期的完整使用统计仍未完成；完整原始活动可分页检查。

### 本机检索观察

使用已有性能脚本，在 Windows / Python 3.14.8 下生成临时的 500 条记忆库，每个场景 30 次采样；新实例场景为 5 次。没有清空操作系统文件缓存，结果不是跨机器延迟承诺，也不衡量语义召回质量。

| 路径的 p95 | 无历史修订 | 每条五个历史修订 |
| --- | ---: | ---: |
| 热缓存只读召回 | 2.74 ms | 3.12 ms |
| 新查询只读召回 | 13.31 ms | 13.66 ms |
| 新实例首次读取和建索引 | 126.86 ms | 184.43 ms |
| 同回合带回执调用 | 82.80 ms | 199.28 ms |

带回执调用包含重复准备，内容不变时可不重写文件；不能将只读热缓存延迟当成实际写回执的延迟。外部实例修改后的首次读取分别为 29.59 / 77.66 ms，脚本同时核对已返回修订后的内容。两组派生索引峰值约 2.43 MiB，临时库约 0.90 / 5.13 MiB。
