# 个性化记忆第二轮复审处理

本轮在 `codex/personal-memory-tui-20261031` 上修复第二轮评审确认的问题，并优化 `/memory` 的直接操作。开始时的 HEAD 为 `98b54b52efbad5d560a9bc687c27364fbe259bf8`，工作区已有未提交实现；本轮保留这些改动。测试使用临时记忆库，没有写入用户的实际记忆。

验收重点是：元数据不能绕过停用和去重；记忆回执可经真实会话事件流到达前端；用户能搜索、查看关联、编辑和批量操作，且失败状态和历史阅读位置可信。

## 两项阻断问题

| 评审项 | 核查与改动 | 行为证据 |
| --- | --- | --- |
| P1 事实判定混入元数据 | `_same_fact` 只比较正文、适用条件、重考虑条件、类型和范围。标题、主题、检索说法、使用频度、待办和关系不再决定事实身份。相同事实的元数据变化要求按原 ID、版本编辑。聊天写入不能借另一条目的更新绕过已停用事实，自动修订也不能指向停用条目。 | 修复前新增的 10 个回归场景全部失败；修复后通过。覆盖主题、别名、常驻偏好与候选、自动生效、明确保存三条路径；拒绝后快照不变，显式修订保留原 ID。 |
| P2 ACP 未声明通知 | 将 `chrys/personal_memory` 加入能力声明，补充通知字段与隐私边界。Smart Test 为扫描服务器源码的 capability 测试增加显式文件依赖，并补对应选路测试。 | 修复前 capability 目录 1 项失败、2 项通过；修复后契约通过。新增测试以模拟模型驱动真实 `ChrysSessionHost`，经 `server.prompt` 发送保存回执，再经实际 headless 事件流发送 CLI 拒绝回执；其他会话和私人条目内容不出现在回执中。 |

“相同事实”仍是保守的字段比较，不宣称任意语义改写均可自动去重。不同情境可以保留不同经验，模型归并仍需原条目版本与证据。

## 易用性修复

| 问题 | 当前行为 |
| --- | --- |
| 搜索每键重绘 | 输入停顿 180 ms 后搜索；Enter、向下键立即提交当前查询。检索索引原本就有增量维护，本轮去掉管理搜索的全条目状态副本，列表内容相同时保留行对象。没有新索引服务或依赖。 |
| 关联跳转受范围限制 | 跳转显式清除类型、主题、搜索和范围限制；已在“全部”页时也能打开跨范围关联。 |
| 编辑器元数据超限 | 主题最多 6 项、每项 1–40 字符；检索说法最多 6 项、每项 2–80 字符。保存前检查，定位并聚焦错误字段；校验失败时不调用保存接口，保留输入供更正。 |
| 管理页泄露模型重试指令 | 已知错误码映射为本地化用户提示；原始详情放在悬停提示中。编辑器保存失败也使用用户可理解的提示。 |
| 历史页被并发写入打断 | 新活动、编辑、设置和召回保留旧页。忘记条目时清除可能含删除内容的页。日志页和快照在同一锁内读取，迟到旧页仍携带旧 generation，不能被错误标成新快照。 |
| 批量重复点击 | 提交期间禁用操作按钮，回复先应用到界面，再恢复操作；丢弃回复前排队的重复操作。失败保留勾选，允许之后重新提交。刷新只保留版本未变的勾选，修改过的条目需要重新核对。25 条限制在界面也有提示。 |
| 保存成功后的失败状态不准确 | 成功后重置失败去重；同内容重复保存仍返回条目确认，清除失败徽章，但不重复弹出保存通知。之后同类失败会重新显示。 |
| 不可用告警刷屏 | 连续读取失败只报告一次，恢复后再次失败才重新报告。仍然返回没有注入记忆的结果，不掩盖错误。 |
| 关闭状态遮住失败徽章 | “未保存”的优先级高于“记忆关闭”，关闭模式下的保存失败可直接看见。 |

真实 TUI 用例覆盖输入防抖、Enter 提交、行复用、跨范围跳转、编辑器校验及别名写入、批量成功与失败、错误提示、历史阅读与忘记，以及失败徽章恢复。额外补测 450 条/85% 容量阈值、25 条原子批量、每页 100 条、15 个不同条目的预算、运行时重建后预算、通用保存的待办重开规则、归档合并来源的版本校验和用量文字渲染。

## 评审意见的边界

- P3 指出的覆盖缺口成立。上一轮通过数是当次选中集合的实际结果，不能证明所有 ACP 契约均已覆盖。本轮显式跑完整 `tests/app/acp/`，并修补选路。没有通过放宽全局超时来消除测试失败。
- P4 对“每键重建整个索引”的描述不准确；原实现按草稿变化增量更新。每键分配副本和重建列表确实存在，已修复。
- P5 的功能文件版权头按目标 iCode 仓库约定统一。`main/screen.py` 的侧栏最小宽度在本轮开始前已经存在，本轮未修改；它属于此前窄屏界面改动。
- `icode run --json` 仍只有原有机器输出，不包含进度回执；中英文个性化记忆指南已明确这一边界。没有扩展 ACP 管理命令或 JSON 输出协议。
- 保留“默认明确要求才写入、开启提炼后明确稳定偏好可生效、推断经验待审核”的既定策略，没有引入逐回合独立模型提炼。
- 原有 `guides/configuration/memory.md`（中英文）未修改，所有产品说明补充在个性化记忆指南中。
