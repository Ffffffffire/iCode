# 个人记忆演示与验收指南

供实现维护者、测试者和演示者使用。用户操作流程见 [中文演示](../../../docs/zh-Hans/guides/configuration/memory-demo.md)；本页给出隔离启动、真实模型证据、确定性回归和失败判定方法。

验收原则：**保存的经验应在适用的未来场景改变判断，并且用户能看见、纠正和停止这种影响。** 保存了多少条、模型声称“记住了”、普通建议碰巧相似，都不能单独证明成功。

当前写入由主智能体按需调用工具，已移除每回合自动提炼和工具内部的模型提炼调用。先验证普通任务只有主模型请求、库不变；再验证明确偏好通过工具保存、推断经验进入待确认。写前使用 `recall_memory(for_update=true)` 比较各状态的条目，核对重复不刷新时间、合并保留条件、并发修订拒绝旧版本。明确失效或完成的条目可通过 `pause_memory` 停用，来源面板应同时显示原证据与停用原因。

## 分层召回与生命周期回归

离线评测由检索维护者和 QA 使用，通过 `scripts/evaluate_personal_memory.py` 加载固定的 `fixtures/recall_cases.json`。场景覆盖格式误触发、命令的输入与输出、标识符、范围、L3 查询和改写对照。标注由 Agent 编写，结合用户明确偏好、会话中的案例和合成条目，待独立复核。评测直接验证本地召回策略。模型是否会在真实任务中及时发出合适的查询，需要单独验证。

`expected` 按 L0—L3 标记必须提供的条目，`forbidden` 指定禁止项，`strict: true` 进一步要求没有任何额外条目。严格用例也要显式标注常驻条目。部分用例只标了必召回项，报告中的 `unlabelled` 可供复核。`searches` 按顺序调用真正的 `recall_memory`，支持 `for_update` 检查与 `alternatives` 改写。改写共用一次 L3 查询，写前检查单独计数。超出搜索预算等工具错误会使案例失败。报告输出四层实际 ID、缺失、额外项及错误，并附语料 SHA-256。

| 验证入口 | 可观察行为 |
| --- | --- |
| `test_recall_eligibility.py` | 超过候选窗口的失效证据或终态待办不能挡住有效记忆；本轮排除和工作区缓存相互隔离 |
| `test_layered_recall.py` | 文件名与自然语言双向匹配；实际工具结果补回；大小写缓存、语言名称和模型名称不串用 |
| `tests/orchestration/engine/test_memory_action_recall.py` | L0/L1 首次到达、L2 工具后补回、L3 查询结果进入实际模型请求；同一版本回执、无额外推理调用 |
| `test_action_recall.py` | 具体动作 × 模式、同一动作去重、并行、取消和失败不吞工具结果 |
| `test_recall_applicability.py` | 独立决定排序、先判相关再去重、格式误触发、关联例外和 L3 改写 |
| `test_recall_evaluation.py` | 样例集消费、错误标注可失败、L3 实际执行、无关注入和预算错误可失败 |

```powershell
uv run python scripts/evaluate_personal_memory.py --output D:/temp/personal-memory-evaluation.json
uv run pytest tests/service/personal_memory/test_recall_eligibility.py tests/service/personal_memory/test_layered_recall.py tests/service/personal_memory/test_action_recall.py tests/service/personal_memory/test_recall_evaluation.py tests/orchestration/engine/test_memory_action_recall.py -n0 -q
uv run python scripts/benchmark_personal_memory.py --size 5000 --iterations 10 --output D:/temp/personal-memory-performance.json
```

性能报告区分新实例、热缓存、未缓存查询、回执落盘，以及包含旧修订导入的第一次落盘。使用临时数据；本机观测值不能充当跨平台固定时限。大库不再限制条数，单文件保留 64 MiB 完整性保护。

新增回归通过实际边界验证：`test_memory_action_recall.py` 检查真实引擎的下一份模型请求；`test_action_recall.py` 检查模式、类别、次数、并行预留、取消和参数不落入回执；`test_scale.py` 检查大库、多窗口、迁移中断恢复和完整历史；`test_consolidation.py` 检查提案、后续回合确认及来源版本；`test_review_policy.py` 检查待复审、候选归档、七天摘要和近似写入；`test_memory_production_ui.py` 检查同一路径的面板行为。最终运行 Smart Test，并只传本次实际改变的文件。

手动验收时，先保存带明确情境的测试记忆，再用不含该主题的任务触发相关文件操作。检查 **本轮参考** 的 L2 标识、工具暂缓回执和目标文件的实际状态，再核对重发后的执行结果。随后检查 **复盘整理** 仅填入输入框、合并提案确认前原条目生效、来源改变后整批拒绝、**待复审** 原因与恢复、**更早修订** 的来源，以及关闭提醒后候选不常驻 Buddy。无反馈的召回可以作为审查信号，错误记忆需要具体纠正证据。

## 启动独立的演示环境

在仓库根目录执行；先完成 `uv sync`，使用本机已经配置且支持工具调用的模型。模型调用使用现有服务并产生正常调用费用。试验脚本不下载模型、不扫描历史会话、不修改真实记忆库。

```powershell
# Windows 控制台和日志统一 UTF-8
$env:PYTHONUTF8 = '1'

# 只列出选择所需的 ID、名称和模型名，不输出密钥或服务请求头
uv run python -c "from chrys.service.profiles.models.registry import ModelProfileRegistry; r=ModelProfileRegistry(); r.load_all(); print([(p.id,p.name,p.model_id) for p in r.list_profiles()])"

# 用实际 ID 替换 <model-id>；完整试验要求一个全新的目录
uv run python -m tests.support.personal_memory_demo --model <model-id> --output D:/temp/memory-demo-01

# 在同一份演示库上打开真实交互 TUI，进行人工体验
uv run python -m tests.support.personal_memory_demo --model <model-id> --output D:/temp/memory-demo-01 --tui

# 自动提交一条真实模型请求，通过 /memory 检查条目并输出 120/80/60 列 SVG
uv run python -m tests.support.personal_memory_demo --model <model-id> --output D:/temp/memory-demo-01 --capture-tui

# 针对现有演示库补测一个问题，证据追加到 trial.json
uv run python -m tests.support.personal_memory_demo --model <model-id> --output D:/temp/memory-demo-01 --query "请查一下个人记忆，再给一个评审决策建议。"
```

macOS/Linux 使用相应绝对目录，设置 `PYTHONUTF8=1` 后运行相同 Python 命令。输出目录包含独立配置、两个空白项目、会话和虚构记忆。脚本仅将平台的配置路径换到该目录，其余使用生产 `bootstrap_runtime`、`ChrysSessionHost`、引擎、工具、存储与 `ChrysApp`。演示智能体不开放 shell、文件读写、MCP 或子智能体，避免与记忆无关的动作干扰观察。

脚本通过当前配置的模型执行请求，不是录播。`--capture-tui` 使用 Textual 的测试驱动操作实际界面和引擎；它证明应用事件链和布局行为，不覆盖每一种原生终端的输入法、字体或鼠标实现。还应在实际终端用 `uv run icode` 和 `/memory` 按中文演示人工检查。

演示宿主沿用 headless 的 `BYPASS` 工具审批模式；来源校验、明确保存检查和候选审核仍然执行。候选经用户启用后生效，与工具调用审批是两道不同的控制。本脚本不验证人工审批弹窗或自动审批模型。若使用要求审批的自定义工具策略，还需在正常 TUI 中验证：拒绝 `propose_memory` 后库不变，允许后仍遵守来源与写入规则。

脚本拒绝写入任意已有非空目录；`--tui` 和 `--capture-tui` 可复用它创建的演示目录。重跑完整试验请换一个新目录，避免旧记忆污染对照。退出 TUI 不会删除演示证据。确认不再需要后可删除自己创建的演示目录；不要删除用户配置目录。

## 18 个真实模型场景

每个编号使用独立会话。同一模型、同一个问题的前后对照能排除会话历史；仍不能消除模型采样差异，因此需要同时核对请求和保存状态。

| 场景 | 输入／设置 | 通过条件 |
| --- | --- | --- |
| 01 无记忆对照 | 关闭记忆，询问评审流程自动发布 | 请求无橙桥内容；答案无虚构的橙桥来源 |
| 02 明确保存 | “请帮我记住……” | 一条有效个人记忆；有原话和条件；无需重复审核 |
| 03 跨会话使用 | 自动模式；不提记忆的原问题 | 首次请求含该 ID/版本；答案体现所存顺序 |
| 04 当前例外 | 只写一句公告 | 可以被检索，但不套用决策方法；不改写记忆 |
| 05 更正 | “请帮我更新这条记忆……” | 同 ID、版本递增、旧内容进入历史；范围与例外保留 |
| 06 更正后使用 | 新会话询问原问题 | 提供新版本；答案采用新顺序 |
| 07 项目保存 | 石杉项目的清单叫杉叶47 | 仅当前项目；包含项目结束等重新核对条件 |
| 08 同项目使用 | 同目录新会话问清单名称 | 提供项目条目；答出独特名称 |
| 09 其他项目 | 切到另一个空目录问相同问题 | 自动与工具检索均无该条目；不能知道独特名称 |
| 10 无关任务 | 数字排序问题 | 不自动注入橙桥和石杉记忆 |
| 11 按需但未请求 | 按需模式询问原问题 | 不自动召回；本次回答不以旧经验为依据 |
| 12 按需且请求 | 明确要求查个人记忆 | 工具返回相关有效条目；本轮参考可检查 |
| 13 已有库但关闭 | 关闭后新会话询问原问题 | 无记忆内容；若工具仍被调用，返回“关闭、未搜索”，不能冒充“库中没有” |
| 14 不要记住 | 建议开启，明确拒绝保存 | 条目和候选均不增加 |
| 15 候选 | 请求待审的北窗项目写作经验 | candidate 状态；原话可核对；尚未生效 |
| 16 未批准候选 | 新会话询问北窗指南 | 候选不作为生效建议召回；仅写前检查可返回候选并标明状态，通用答案不能冒充该候选的证据 |
| 17 停用 | 停用橙桥后新会话询问 | 不提供该条目；它仍存在于已停用列表 |
| 18 忘记 | 忘记石杉条目后新会话询问 | 有效条目、历史、待审修订、召回引用均不再含该 ID；答案不能从库中找回 |

`trial.json` 每个场景保留输入、工作目录标识、会话 ID、回答、提供给 wire client 的消息、运行后库快照和耗时。记录点在协议编码前；没有记录 HTTP 密钥或请求头，不应称为抓包。`seconds` 是这个环境下单次运行时间，不能直接当作 memory 开销；`requests` 的长度是 provider acquisition 次数，不是 token 用量或费用。

人工复核每项时，记录 `通过／失败／未执行` 与具体证据。不要只搜索最终回答中的关键词。对保存查看工具返回与快照；对自动召回查看第一份请求最后一条用户消息中的 `personal_memory`；对按需召回查看工具结果；对纠偏比较 ID、版本、条件和历史；对模型采用查看回答中的实际行动顺序。

## TUI 验收

通过实际输入框键入 `/memory`，不要只直接构造记忆窗口。至少在中文 120×42、80×32、60×28 和英文常用宽度检查；人工检查所用终端的缩放、中文字符宽度和鼠标。

| 操作 | 观察点 |
| --- | --- |
| 输入 `/memory` 或点击底部记忆入口 | 正确打开；没有候选时不打断聊天 |
| `Ctrl+N` → 输入正文 → `Ctrl+Enter` | 光标在正文；不必展开更多选项；默认当前项目 |
| 编辑来源、条件与范围 | 动态文字无 Rich markup 解释；长文本可滚动；保存后选中实际条目 |
| 更改标题后重复保存相同事实 | 不新增副本；仍定位原条目；不伪造新来源 |
| 输入超过 2,400 字符后保存 | 明确失败，保留草稿与类型、范围，允许修正重试 |
| 查看本轮参考 | 匹配词、查询和版本可见；明确“提供”不等于“已采用” |
| 本轮先命中再搜索无结果 | 先前已提供的参考仍可见；下一回合重新开始记录 |
| 自动改按需／关闭后开始新回合 | 清除上一回合参考数；按需查询可重新产生参考 |
| 查看候选，记住／忽略 | 来源默认可见；处理后进入下一条；未确认不用于召回 |
| 旧修订候选覆盖新编辑 | 拒绝，保留新版本；提示刷新核对 |
| 停用 → 恢复 → 忘记 | 控件状态正确；忘记需确认；取消不会删除 |
| 搜索、键盘、退出 | `Ctrl+F` 聚焦搜索，`↓` 进列表，`Esc` 返回聊天；底部快捷键不被挤掉 |
| 调整窗口宽度／切换明暗主题 | 列表、详情、主要动作可到达；60 列用纵向布局，无横向溢出 |

自动截图为 `chat.svg`、`memory-120.svg`、`memory-80.svg`、`memory-60.svg` 和存在候选时的 `candidate.svg`。截图不是静态设计稿。`tui-answer.txt` 保留通过实际输入框发送问题后收到的真实模型答案；`tui-snapshot.json` 记录界面审核后的库状态。

同时保留 `.raw.svg` 原始导出。当前 Rich 导出器用字符个数设置 `textLength`，而文本坐标使用终端单元格数，直接显示中文会挤在一起。脚本只将这个导出宽度改为 `rich.cells.cell_len` 对应的宽度，不改变内容、布局坐标或配色。自动截图也去掉外层测试终端的 `NO_COLOR` 等变量，与仓库现有 TUI 测试一致；交互模式仍尊重用户终端设置。

## 确定性边界与故障测试

这些场景用生产存储、运行时和真实引擎配合受控模型，故障可重复，不依赖模型是否恰好选择某个工具。

| 边界 | 自动用例位置／通过条件 |
| --- | --- |
| 中英文明确请求、礼貌前缀 | `test_runtime.py`：自然请求有效；否定、代码、引用不成为授权 |
| 不保存与历史重提 | `test_runtime.py`：开启建议仍拒绝；后续回合不能拿拒绝原话再提候选 |
| 来源归属 | `test_runtime.py`、引擎 `test_personal_memory.py`：伪造引文拒绝；偏好、决定、意图必须有用户来源 |
| 长度和适用条件 | 聊天正文最多 600 字符，附应用的经验正文合计最多 1,600 字符。聊天写入需要适用条件，手写允许 2,400 字符且条件可选 |
| 去重与显式冲突 | `test_store.py`：同事实复用；同主题同条件冲突拒绝；不同条件可共存 |
| 修订与并发写 | 同 ID 版本递增；陈旧版本不能覆盖新版本；接受候选和恢复也检查新冲突 |
| 项目边界 | 当前项目＋个人可读；其他项目不可召回，也不能猜 ID 后用聊天修改 |
| 候选与状态 | 未批准、停用不作为生效建议召回；关闭停止聊天读写，手动编辑器仍可使用；写前检查不记录为生效召回 |
| 检索预算 | 单次 ≤5 条/6,000 渲染字符；一回合 ≤3 次额外工具检索、15 个不同条目、18,000 渲染字符，重建 runtime 不重置；写前检查独立为 ≤8 条/12,000 字符；无结果不创建空库 |
| 多次搜索记录 | 同回合合并已提供的引用；空搜索不抹掉已有引用；下一回合重置 |
| 按需检索的原问题保留 | 模型缩写词无匹配时，以本轮用户原问题补查；仍遵守模式、范围、状态和单次预算 |
| 损坏文件 | 报告不可用，不把损坏数据静默覆盖成空库 |
| 删除完整性 | 清除当前条目、历史、待审修订与召回引用；不承诺删除会话文本 |
| 会话／执行域隔离 | `tests/orchestration/invoker/test_runtime_recipes.py`：私人库不自动提供给子智能体和工作流；引文来源不串会话 |

定位失败时可先运行：

```powershell
uv run pytest tests/service/personal_memory tests/orchestration/engine/test_personal_memory.py tests/app/tui/screens/test_personal_memory.py -n0 -q
```

修改完成后必须用 Smart Test 收口，传入**本次任务实际修改**的所有路径，不把用户原有未提交修改混入范围。例如只修改 runtime/store 和相关测试时：

```powershell
uv run python scripts/chrys_test.py --smart --paths src/chrys/service/personal_memory/runtime.py src/chrys/service/personal_memory/store.py tests/service/personal_memory/test_runtime.py tests/app/tui/screens/test_personal_memory.py
```

本次如果还修改文档、演示脚本、清单，也加入命令。不要手算最终受影响测试集合。Smart Test 不等于全仓测试；只有明确需要完整本地非集成测试时才运行 `--full`。

另外对改动文件执行 Ruff 无修改检查和格式检查；运行仓库规定的 win32/linux/darwin 类型检查、i18n 检查。修改异步等待时刷新 `tests.support.trajectory_wait_inventory` 并核对变化。新增显示文案才走完整翻译流程，且不得与 pytest 并发。保存每条命令的退出码和完整日志；失败区分产品问题、测试驱动问题和环境问题，不把环境猜测当作已证实根因。

## 当前能力边界与后续观察

- **语义召回**：中文双字词和英文词项匹配，不保证跨主题联想。用“改写但语义相同”的问题补充观察，记录漏召回；不要把未实现的 embedding 或 dream 当作已有能力。
- **内容价值**：长度、来源和状态检查能约束写入，却不能证明提炼忠于原文或经验正确。人工检查模型是否扩大适用范围、添加未说过的理由、把失败泛化为负面判断。
- **纠偏**：明显同主题冲突会拦截，改写后的语义冲突没有完备算法。核对更正是否保留例外，遇到不确定结论先停用。
- **时效性**：重新考虑条件是提供给模型的文字，易变事实使用前要核实。接受的待办有独立状态和可选提醒时间；验证等待、稍后、完成、取消在跨会话后仍成立。单次例外、年龄和低频使用不能替代失效证据。
- **预算**：正常召回受单次及整回合预算约束；自动重复提供相同版本不重复计费，主动工具返回的内容计入字符预算。写前检查是独立候选列表，仍有工具和上下文成本，不能宣称已经检查整个库。真实模型试验同时记录查询次数和写前检查次数。
- **压缩与资料**：已启用建议时，实际提交的模型摘要可带出最多两条待审候选；原始用户引文必须可核对，不额外调用提炼模型，也不把加载文件当作个人选择。覆盖提交失败、重复压缩、拒绝后重提、来源串会话等边界。
- **组织级共享**：本地项目条目仍属个人库；当前没有团队发布、权限审批或多人合并流程。组织提取与治理应另行验收。

后续真实使用时，优先记录“本该想起但没想起”“记忆被错误套用”“纠正后仍反复出现”“没必要的建议打扰”四类具体事件。每条附当前任务、记忆 ID/版本、原始来源与实际回答，才能决定应改检索、内容、条件还是交互。

## 类型、跟进和反馈的验收路径

1. 在隔离记忆库保存一个带主题的偏好和一个有日期的意图。通过真实 `/memory` 入口按类型、主题和工作区筛选；60、80、120 列均可操作。
2. 普通任务的召回记录为 `provided`；工具 `review_memory(applied)` 单独记录 Agent 声明，不能产生用户肯定。无原话的 helpful/incorrect 拒绝；用户明确错误或 UI 点“错误”后停用。
3. “这次不用”在同一回合的后续查找中排除，下一回合可重新召回；重复用户文字也应形成不同回合。另一个项目不能按 ID 越界反馈或修改。
4. 接受跨会话待办，重建 Store 后验证到期召回；完成后不再提醒。点击“继续”只填入普通输入框，不发送、不改写已有草稿，也不修改会话 Todo。
5. 归纳两条经验得到候选方法；确认前不召回，确认后可由来源关联找到。更新来源后停止召回；对原方法提出带新来源版本的修订候选，接受后沿用原 ID。
6. 合并时给一个陈旧版本，检查完全没有部分更改。忘记来源要清理派生条目、版本和完整日志；模拟日志清理失败，先报告未完成，再重试完成物理清理。
7. 产生超过 128 条活动，验证 UI 截取不丢完整日志；模拟截断尾行和提交后追加失败，恢复后序号无重复。

对应自动用例为 `test_management.py`、`test_lifecycle.py`，TUI 的 `test_memory_management.py` 及引擎的 `test_personal_memory.py`。这些确定性测试验证执行路径；真实模型是否主动识别有价值线索、是否忠实归纳，需要继续用实际任务观察，不能由 MockChatClient 的通过推断。

评审修复的边界用例在 `test_review_fixes.py`：旧格式只读不改写、可见历史引证、候选查重、关联版本失效、终态待办重开、召回总预算、批量原子性、历史分页和日志超量拒绝。真实 `/memory` 入口及跨会话反馈见 `tests/app/tui/screens/test_memory_review_fixes.py`；ACP 回执需验证只包含本次操作，不包含整个私人库。

## 工具调用统计

每次记忆工具调用的结果都会写进会话轨迹（`memory.save.committed`、`memory.save.rejected`、`memory.recall.served`、`memory.consent.resolved`），只记错误码、条目数、字符数与视图名，不含标题和正文。用它统计一次会话或整个会话根目录：

```bash
uv run python scripts/memory_traffic_report.py                 # 所有会话
uv run python scripts/memory_traffic_report.py --session <id>  # 单个会话
uv run python scripts/memory_traffic_report.py --json          # 机器可读
```

输出给出写入失败率（拒绝数除以拒绝加提交）、按错误码的分布、召回的条目数与字符数、每次提交对应几次召回，以及确认结果的计数。改动记忆写入或召回逻辑后，用同一份数据前后各跑一次，就能看出是变好还是变坏。
